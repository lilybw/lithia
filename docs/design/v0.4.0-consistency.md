# v0.4.0: emptying spec section 14

Goal: every entry of v0.3.1's section 14 ("Temporarily tolerated behavioural inconsistencies") is either
fixed or stated as a rule where it belongs, so the section ends up empty. lithia is the general-purpose
core of a family (LiSP for signal processing, lithia-gui): what only a restricted domain could fix is a
rule of the core, not an exception, and restrictions belong in the variants.

Decisions (Lily, 2026-11-18): async runs guarantee progress; every body form sees its captures by
reference; all three cycle and epoch entries are fixed; by-design entries move into their sections.

## Stages

Each stage is implemented, tested (validation cases, edge tests, loom models, mutation checks) and
committed before the next. The spec is written last, as v0.4.0, from the implementation.

### 1. Macro, diagnostics, test utilities

| v0.3.1 entry | Change |
|---|---|
| Captures: `T` in synchronous bodies, `&T` elsewhere | Every body form binds its captures by reference. |
| `move` means different things | `move` moves the outer values instead of cloning them, in every form; field paths refine it too. |
| `async move` source block needs only `Send + 'static` | Bounds follow from what the form does: cloning needs `Clone`, sharing across runs needs `Sync`, threads need `Send + 'static`. Stated as the rule. |
| `ALWAYS_PROPAGATE` without `equals`: error or panic | Accepted everywhere: without `equals` every write already propagates. |
| Effect cuts logged at trace | Logged at debug. |
| Duplicate keys at debug | Warned. |
| Reclaimed node keeps first options | Fragility, ghost policy and flags join the reclaim conditions. |
| Unread-memo warning only at sweeps | Also checked when a memo loses its last child or `changes()` stream. |
| `settled` ignores writes out of the subtree | `settled` follows the epochs the subtree's writes start. |
| New child of a ghost panics | A new child of a ghost behaves like a surviving child. |

Settled by the implementation:

- Reclaiming: fragility, ghost policy and flags are part of a keyed node's identity (a `Shape` the
  macro evaluates once, before the lookup). A comparator cannot be compared, so a reclaimed node takes
  the creation's `equals`, unchanged or not, before a refreshed source node's write. `init` is the
  value before a node's first run; a reclaimed node has run, so it keeps its value.
- Unread memos: checked when a memo loses its last child, `changes()` stream or captured handle.
- `settled` walks write edges and the nodes a run wrote without an edge (noted per writer).
- A node created with ghost parents is linked as a surviving child; with only ghosts, disposed at
  once. Found by loom and fixed with it: a child linked while its parent was being disposed was
  missed (teardown now hands back the children linked when the parent closed), and a run decided
  before a parent failed could publish over a fragility failure (fragility is checked again when a
  run starts, and fails a run in flight).

### 2. Lifetimes

| v0.3.1 entry | Change |
|---|---|
| Handle moved out of an `async move` block uncounted | Handles moved into a block start counting when the block ends while they live on. |
| Letting go is final | An anchor's return holds its unsupported, still-living descendants again. |
| Old child runs once more on new input | A creator decides its children before they run in an epoch. |

Settled by the implementation:

- A handle a `move` body takes over is leased to the expansion. An async source block ends its
  lease when it completes or is dropped, and, ahead of the support that changes with it, when its
  node is disposed, freed or refreshed; each leased handle still alive then counts as an outside
  handle. Other body forms see their captures by reference, so nothing leaves them.
- An anchor count rising from zero walks downstream, under the sweep lock, and holds again every
  live node support would hold that it reaches, stopping at nodes support still holds.

### 3. Protocol

| v0.3.1 entry | Change |
|---|---|
| Async node starves under fast input | A run that replaced another is not replaced itself; inputs meanwhile coalesce into one rerun after it ends. |
| Fragility bypasses versions | A parent's status change is a versioned change that only fragile children see. |
| Loops through creation spin | A created child's writes are attributed to its creator's creation site, so a loop through creation is cut. |
| Cut writer keeps a stale result | A cut writer reruns once at the end of the epoch, with writes to targets it already wrote suppressed. |
| Joins may mix epochs | An opt-in flag keeps a join to one epoch. |

### 4. Moved into their sections as rules

Top-level node on long-lived state; self-support; effects held in a replaced value; `.scoped()` is
node-level; `Accessor` anchoring by kind; keyed identity includes parents and write targets; opaque

unsupported node's first run (7.5); what Loud Failures cannot see (1).
